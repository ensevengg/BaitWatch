# Sandbox boundary

The runner talks to a local Linux Docker daemon. It creates resources through the Docker API, then starts the container with a Docker attach client on the host and streams the output. The repository's command arguments go only into the container definition. The runner never executes a repository script on the host.

Each scan follows these steps.

1. **Stage a copy.** The runner copies the repository into a disposable directory. It walks the tree with file-descriptor-relative opens that never follow a symlink, even when a file turns into a symlink during the copy. It copies symlinks as symlinks. The copy fails on regular files with more than one hard link, on devices, sockets and FIFOs, and when it passes the limit on entries, bytes, depth or time. It leaves out Git metadata, dependency and cache environments, credential-store directories and real `.env` files, and lists each one in `staging_exclusions`. It keeps `.env.example` and agent hook or settings directories. An excluded path was not scanned. The copy is not an atomic Git snapshot, so a repository that changes during the copy can make staging fail.
2. **Create the network.** The runner creates a uniquely named internal bridge and labels it with the scan. It tries the default subnet `10.13.37.0/24` first. If Docker reports that the range is taken, it retries other subnets under `10.13.0.0/16` in random order, up to 16 attempts in total. The cage is `.20` on the chosen subnet. Sinks get fixed host offsets, `.53` for DNS and `.9` for HTTP and TLS. A configured subnet is used as written and never falls back. The network uses Docker's isolated gateway mode, so the host gets no address on it and the cage cannot reach the host. If the engine still assigns a host gateway, for example because it is older than Docker 28, the scan fails with a setup error. The runner never joins a default or public network, never publishes ports, and never reuses a network that already exists.
3. **Restrict the cage.** The container runs as uid and gid `65532:65532` with a read-only root filesystem. Its only writable mounts are a small `/tmp` and the staged copy of the repository at `/repo`, which is writable on purpose so the scan can detect what the cage changed there; the original repository is never mounted. The staged copy carries permissive mode bits for the cage's uid but lives under the scan's `0700` directory, where no other host user can reach it. The container drops all capabilities, sets no-new-privileges, and has memory, CPU and PID limits. The runner never mounts home directories, credentials, host devices or the Docker socket. It sets the container environment explicitly and copies no host secrets into it.
4. **Bound execution.** By default, stdout and stderr share a 64 KiB budget and the command has 20 seconds. Going over either limit stops the container. The attach client has its own limits and the runner always reaps it. A missing local image is an error. Pull images during trusted setup, before any scan.
5. **Run the sinks.** `start_sinks()` starts the DNS sink on `.53` and the HTTP/TLS sink on `.9` as their own hardened containers (same restrictions as the cage, plus the namespaced low-port sysctl and no network egress beyond the scan network). Each sink appends JSONL evidence to a per-scan log file. The runner waits for each sink's `ready` record within a bounded deadline; a sink that dies or never reports is an error, never a silent gap.
6. **Trace the staged tree.** Before and after the command, a short-lived helper container — same image restrictions and limits, no network, staged copy mounted read-only — snapshots the tree with fd-relative walks that never follow symlinks, hashing files and recording unreadable entries as error markers. The runner parses each manifest strictly and diffs the two into `file_diffs`. Any failure, including timeouts, oversized manifests or tampered output, marks the trace component error. Snapshots run as uid 65532 in a container because the cage can leave files the host user cannot read.
7. **Clean up.** The runner removes only the resources this scan created, including when an exception interrupts it. It records cleanup failures. If the runner cannot remove a container, it keeps the staging directory so an operator can recover it. Cleanup also removes anything the daemon still lists under this scan's label, so a resource from a create call that lost its reply does not leak. The cage's uid can create directories the host user cannot delete, so when removal of the staging directory fails, a trusted helper container running as that uid makes every directory it owns writable and traversable again, without following symlinks, and removal is retried. A staging directory that still cannot be removed is recorded as an error, never leaked silently. A resource the daemon creates after cleanup has run, or a crash of the process or host, can still leave labelled resources behind. Recover them by filtering on the scan label. Never run a global Docker prune.

## Known limits

- The cage cannot reach public addresses or the host over the network. It can still reach the other containers on its own bridge, which are the sinks. This milestone makes no claim of resistance to kernel or container escapes.
- The sinks see only what crosses the scan network. Attacks using channels the sinks do not cover, for example non-DNS UDP protocols or TLS bodies (only the ClientHello SNI is logged), do not light up. Later milestones add TLS body capture and honeytoken attribution.
- This branch does not ship the decoy agent (added in PR #12), honeytoken attribution, model transcript scanning or verdict fusion. Without a decoy, the decoy component stays `not_run` and every scan stays incomplete. The PR #12 trial against repo #1 produced 0/10 bites; see `docs/DECOY_TRIAL.md`.
- Automatic subnet selection tries up to 16 subnets. If every candidate is taken, for example by many concurrent scans or a VPN that covers most of the range, the scan fails closed instead of sharing a network.
